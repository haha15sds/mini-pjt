## 1회차 → 3회차 (수정 후)

| 판정 | 1회차 (수정 전) | 2회차 | 3회차 (최종) |
|---|---|---|---|
| 좋음 | 0 | 8 | **7** |
| 단정 (증상에 끼워 맞춤) | 3 | 0 | 1 (M01) |
| 숨김 (실제 문제 누락) | 3 | 0 | 0 |
| 지어냄 (테넌트에 없는 장애) | 2 | 0 | 0 |

**수정 내용** (`src/agent.py` [불일치 대응], `src/tenant.py` `supported_faults`)
- 진단 스키마에 `symptom_matches`(문의 증상이 점검 결과로 설명되는가)를 추가하고, 증상에 끼워 맞추는 연결 문장과 문의 진술만으로 테넌트에 없는 장애를 내는 것을 금지.
- 코드 검증: 테넌트 점검에서 근거가 확인되는 장애만 원인으로 남기고(없는 장애 제거), 빠진 실제 문제는 보충. 불일치면 확신도 0.5 이하, 요약에서 연결 문장 제거, 조치 단계를 실제 문제의 조치 + '증상 원인 추가 확인'으로 교체, 답변에 "문의하신 증상은 테넌트 점검 결과로 설명되지 않습니다…확인 필요" 문장.
- 승인 카드의 조치는 1순위 원인과 같은 장애의 것만.

**2회차 → 3회차**: 2회차는 규칙상 8/8이었지만 답변을 직접 읽어 보니 연결 문장이 남고(M01) 승인 카드에 증상 쪽 조치가 뜨는(M02) 문제가 있었다. 요약 정리·조치 교체·승인 조치 정렬을 더하고, 판정에 '승인 카드 조치가 실제 장애의 것인가'를 추가했다.

**남은 한계 (M01)**: 모델이 "겸직자만 안 보인다"는 증상을 사이트 권한 누락으로 설명할 수 있다고 판단해(symptom_matches=true) 불일치 처리가 시작되지 않았다. 증상과 원인이 맞는지 판단하는 것은 여전히 모델 몫이라, 그럴듯한 연결이 가능하면 놓칠 수 있다.
