# 불일치 점검 (M 세트) — 문의 증상과 테넌트 상태가 어긋날 때

정식 18건의 문의 글을 그대로 쓰고 시나리오만 다른 장애로 바꿔 짝지었다. 정식 평가와 별개다.

**결과: 좋음 0 · 단정 3 · 숨김 3 · 지어냄 2 (총 8)**

| id | 문의(증상 장애) | 시나리오(실제 장애) | 원인 후보 | 1순위 확신도 | 불일치 표시 | 판정 |
|---|---|---|---|---|---|---|
| M01 | P6 (F5) | S04 (F6) | F6 | 0.95 | 아니오 | 단정 |
| M02 | P1 (F1) | S06 (F5) | - | - | 예 | 숨김 |
| M03 | P4 (F6) | S03 (F4) | - | - | 예 | 숨김 |
| M04 | P3 (F4) | S02 (F2) | F4 | 0.85 | 아니오 | 지어냄 |
| M05 | P2 (F2) | S05 (F3) | F2 | 0.95 | 아니오 | 지어냄 |
| M06 | P5 (F3) | S07 (F4) | F4 | 0.95 | 아니오 | 단정 |
| M07 | P7 (F1) | S04 (F6) | - | - | 예 | 숨김 |
| M08 | E3 (F4) | S06 (F5) | F5 | 0.95 | 아니오 | 단정 |

판정 기준: 좋음 = 실제 장애를 알리고 불일치·확인 필요를 밝힘 / 단정 = 실제 장애를 확신 있게 원인으로 단정 / 숨김 = 실제 장애를 알리지 않음 / 지어냄 = 테넌트에 없는 장애를 원인으로 냄

## 분석 (1회차, 수정 전)

바람직한 답(좋음)은 8건 중 0건. 실패는 세 가지 모양으로 나뉜다.

| 모양 | 케이스 | 무슨 일이 있었나 |
|---|---|---|
| 증상에 끼워 맞춤 (단정) | M01, M06, M08 | 테넌트에서 보이는 장애를 1순위로 내고(확신도 0.95), 문의 증상을 그 장애로 설명하는 이야기를 지어냈다. 예: M01은 "임원·겸직자는 연구소 사이트를 주로 써서 안 보인다"는, 어디에도 근거 없는 연결 문장을 만들었다 |
| 문의 말을 더 믿음 (지어냄) | M04, M05 | 테넌트에는 없는 장애를 문의 내용만 보고 원인으로 냈다. 예: M04는 "계정 표기를 대문자로 바꿨다"는 문의 문장을 근거로 F4를 진단했지만, 테넌트의 식별자는 모두 정상이다 |
| 불일치는 짚었지만 실제 문제를 빠뜨림 (숨김) | M02, M03, M07 | "문의 증상과 테넌트 상태가 일치하지 않아 추가 확인이 필요하다"고 밝힌 것은 좋다. 그러나 테넌트에 실제로 있는 다른 문제(M02의 그룹 한도 초과 등)는 알리지 않았다 |

- 세 번째 모양은 거짓 주장이 없어 가장 안전하고, 실제 문제만 덧붙이면 '좋음'이 된다.
- 첫 두 모양은 관리자를 잘못된 조치로 이끌 수 있다. 특히 끼워 맞춤은 확신도가 높아 위험하다.
- 원인: 계획 단계 규칙이 "원인은 findings에서만 고른다"와 "summary는 원인을 설명한다"만 있어서, 증상과 findings가 맞지 않을 때 어떻게 할지 정해져 있지 않다.
